מצילומי הבדיקה לדו"ח קליני מלא ב-Word, בלחיצה אחת From exam screenshots to a finished clinical Word report, in one click

כלי שבניתי למעבדת יציבה והליכה. הרופא מדביק בדו"ח את צילומי DIERS, ‏Stabilimeter ו-Pedogait כרגיל. התוכנה ממלאת את טבלאות המדדים מהצילומים, כותבת ניתוח קליני מתחת לכל צילום ומסכמת הכל בדיון, ישירות בתוך קובץ ה-Word, בעברית ובעיצוב של הדו"ח.

A Windows tool I built for a posture and gait lab. The physician pastes the DIERS, Stabilimeter and Pedogait screenshots into the report as usual. The tool fills the measurement tables from those screenshots, writes a clinical analysis under every image and closes with a discussion, directly inside the Word file, in Hebrew, in the report's own layout.

כאן הרופא היה מעתיק את המספרים וכותב את הניתוח ביד
  • ממצא כללי: הסטה צידית בינונית של הגו ימינה מעל האגן, עם עקמת קלה ואגן אסימטרי בדפוס פיצוי תפקודי.
  • מישור קורונלי: הסטה של האגן (Coronal Imbalance) 9 מ"מ שמאלה - בינונית; עקמת 8°‏ שמאלה, אפקס T7‏ 6 מ"מ ימינה - קלה.
  • מישור סגיטלי: הסטה קדמית של הגו (Sagittal Imbalance) 41 מ"מ - משמעותית; קיפוזיס 54°‏ תקין, לורדוזיס 39°‏ גבולית.
  • רוטציה חולייתית: רוטציית פני השטח (Surface Rotation) עד כ-4°‏ בתבנית מתחלפת לאורך העמוד - קלה.
  • אגן ותבנית פיצוי: הרמה אגנית (Pelvic Obliquity) 5 מ"מ משמאל - קלה; רוטציה 3°‏ ימינה, Torsion 2°‏ תקין; הגו מפצה ימינה.

מבחינה תפקודית, הסטת הגו ימינה מעל אגן מורם משמאל ונשיאת משקל עודפת על ימין (54%) מעמיסות על SIJ וירך ימין, בהתאם לרגישות ולהגבלת הכיפוף מימין. ההסטה הקדמית מעמיסה על מיישרי הגב ומסבירה החמרת כאב בעמידה ממושכת; נדרש שיפור שליטה אגנית ואבדוקטורית.

  • תנודה קדמית-אחורית (Sagittal Sway): שמאל 11.8 מ"מ ובעצומות 15.2 מ"מ, חורגת מאליפסת הנורמה, ימין 7.4 מ"מ - בינונית.

דיון :

כאן הרופא היה כותב סיכום, תובנות, מסקנות והמלצות, על בסיס כל הסעיפים

סיכום:

בן 46, עובד משרד, עם כאבי גב תחתון (NSLBP) מזה שנתיים, ללא אירוע טראומטי, המוחמרים בעמידה ממושכת ובסוף יום עבודה. הממצאים מצביעים על חוסר איזון פוסטורלי עם הסטה קדמית וימנית של הגו, נשענות על ימין ושליטה פוסטורלית התלויה בראייה, המעמיסים על מיישרי הגב ועל SIJ ימין.

ממצאים מרכזיים:

  • בדיקה פיזיקלית: הגבלה קלה בכיפוף ירך ימין 110°‏, קיצור דו-צדדי של Hamstrings עם SLR‏ 60°‏ ורגישות קלה מעל SIJ ימין; כוח ותחושה שמורים.
  • יציבה (DIERS): הסטה קדמית של הגו (Sagittal Imbalance) 41 מ"מ, משמעותית; הסטת אגן 9 מ"מ שמאלה, בינונית; הרמה אגנית 5 מ"מ משמאל ועקמת 8°‏, קלות.
  • עמידה ויציבות (Stabilometer): נשיאת משקל ימין 54% ועומס קדמי 44%, שניהם עולים בעיניים עצומות; תנודה סגיטלית בשמאל ותנודת ליבה צידית חורגות מהנורמה, בינונית.
  • הליכה: לא הוצג ניתוח הליכה בדו"ח, ולכן לא ניתן להעריך כיצד הממצאים הסטטיים מתבטאים בתפקוד הדינמי.

תובנות:

  • ההסטה הקדמית של הגו והעומס הקדמי מחייבים הפעלה מתמשכת של מיישרי הגב, וזה מסביר את החמרת הכאב בעמידה ממושכת ובסוף היום.
  • הגו מוסט ימינה מעל אגן מורם משמאל, והמשקל נישא בעיקר על ימין; יחד הם מרכזים עומס על SIJ וירך ימין ותואמים את הרגישות ואת הגבלת הכיפוף מימין.
  • ההחמרה בעיניים עצומות מעידה על הסתמכות חזותית ועל שליטה פרופריוצפטיבית אגנית-ליבתית מופחתת, ומכאן עלות אנרגטית מוגברת ועייפות בסוף היום.

מסקנות:

  • הבעיה התפקודית המרכזית היא חוסר איזון פוסטורלי סגיטלי וקורונלי עם שליטה אגנית-ליבתית מופחתת, היוצר עומס סטטי מתמשך על מיישרי הגב ועל SIJ ימין.
  • הקורלציה בין האנמנזה לממצאים גבוהה: אופי הכאב והגורמים המחמירים אותו תואמים את דפוס העומס שהודגם בעמידה.

יעדי טיפול והמלצות שיקומיות:

  • להעביר את מרכז הכובד אחורה ולהפחית את ההסטה הקדמית: אימון יציבה עם משוב חזותי, הפעלת השרשרת האחורית ותרגול Hip Hinge.
  • לאזן את נשיאת המשקל בין הגפיים: תרגילי Weight Shift שמאלה עם משוב ותרגול נשיאה חד-רגלית על שמאל.
  • לחזק את השליטה האגנית, האבדוקטורית והליבתית: חיזוק Gluteus Medius, ‏Side Plank וייצוב ליבה דינמי.
  • לשפר את השליטה הפרופריוצפטיבית: אימון שיווי משקל על משטחים לא יציבים, עם מעבר הדרגתי לעיניים עצומות.
מה קרה כאןWhat happened here

התבנית מגיעה עם יחידות ומקומות ריקים. התוכנה קראה את טבלת הפרמטרים בצילום DIERS פעמיים (פעם בתמונה המלאה ופעם בחיתוך מוגדל), השוותה, וכתבה רק ערכים ששתי הקריאות הסכימו עליהם. שורה שחסרה בתבנית נוספה.

The template ships with units and blanks. The tool read the DIERS parameter table twice (full image and a zoomed crop), compared the reads and wrote only values both agreed on. A row missing from the template was added.

הוראה קבועה, לא צ'אטA fixed instruction, not a chat

לכל סעיף יש קובץ טקסט שהרופא ניסח: מה לקרוא בצילום, אילו נורמות, איך לדרג חומרה ומה המשמעות התפקודית. כך כל דו"ח כתוב באותו מבנה ובאותה שפה, והרופא משנה סגנון בלי לגעת בקוד.

Each section has a text file written by the physician: what to read in the image, which norms apply, how to grade severity and what it means functionally. Every report gets the same structure and voice, and the physician changes the style without touching code.

שני מצבים, טבלה אחתTwo conditions, one table

התוכנה מאחדת את צילומי העיניים הפקוחות והעצומות לטבלה אחת, צובעת ירוק/אדום ומדגישה ערכים מחוץ לנורמה, ואז כותבת ממצאים, משמעות קלינית ומסקנה.

The tool merges the eyes-open and eyes-closed screenshots into one table, colours them green/red, bolds out-of-norm values, then writes findings, clinical meaning and a conclusion.

דיון אינטגרטיביIntegrative discussion

הדיון נכתב אחרון ומחבר בין האנמנזה, הבדיקה הפיזיקלית וכל הסעיפים. כשסעיף חסר (כאן: הליכה), הוא אומר זאת במפורש ולא ממציא.

The discussion is written last and ties together history, physical exam and every section. When a section is missing (here: gait) it says so explicitly instead of inventing it.

הרופא נשאר בשליטהThe physician stays in control

בחירת סעיפים, דגש אישי לכל סעיף, ניסוח מחדש (קצר / מפורט / פשוט) ונעילת טקסט שאושר כך שהרצה חוזרת לא תדרוס אותו.

Pick sections, add a per-section emphasis, rephrase (shorter / more detail / simpler), and lock approved text so a re-run never overwrites it.

ארכיטקטורהArchitecture

הכל רץ על המחשב במרפאה. אין שרת ביניים ואין מסד נתונים; רק טקסט מותמם וצילומי הבדיקה יוצאים ל-Claude.Everything runs on the clinic PC. No middle server and no database; only de-identified text and the exam screenshots go to Claude.

‎1-7 הם השלבים בתוך המנוע. השלבים 2-5 רצים לכל סעיף ולכל תמונה במקביל. 1-7 are the engine steps. Steps 2-5 run for every section and every image in parallel.

פרטיות ובטיחותPrivacy and safety

כלי קליני צריך להיות משעמם מבחינת אבטחה. אלה הכללים שהוא בנוי עליהם.A clinical tool should be boring about security. These are the rules it is built on.

התממה לפני שליחהDe-identify before sending

שם, ת"ז, תאריך לידה, טלפון ומייל מוסרים מהטקסט. שם הקובץ לא נשלח. הצילומים מהמכשירים לא כוללים פרטי מטופל.

Name, ID, birth date, phone and e-mail are removed from the text. The file name is never sent. The device screenshots carry no patient details.

בלי שרת ובלי מסדNo server, no database

התוכנה רצה מקומית. הקבצים עצמם לא עולים לענן, ויומן השימוש שומר רק תאריך, סעיפים, מודל ומשך.

It runs locally. The files themselves never go to the cloud, and the usage log keeps only date, sections, model and duration.

אדם מאשרA human signs off

המקור לא משתנה, כל הרצה יוצרת עותק, וטקסט שהרופא אישר ננעל. ערך שאין עליו הסכמה בין הקריאות לא נכתב.

The original never changes, each run makes a copy, and approved text is locked. A value the reads disagree on is not written.
